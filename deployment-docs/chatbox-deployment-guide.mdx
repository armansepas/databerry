# Chaindesk Chatbox Deployment Guide

## Overview

This guide explains how the Chaindesk chatbox/bubble widget works, how to serve it locally, and how to deploy it to a CDN for production use. The chatbox system is built with modern web technologies and can be embedded as either a bubble widget or an iframe.

## What We Did - The Complete Process

### 1. Understanding the Architecture

The Chaindesk chatbox system consists of several key components:

- **Embeds Package** (`packages/embeds/`) - The core widget JavaScript bundle
- **UI Components** (`packages/ui/`) - React components for the chatbox interface
- **Build System** - ESBuild configuration for bundling and serving
- **Test Environment** - Local development and testing setup

### 2. Tech Stack Breakdown

#### Core Technologies
- **ESBuild** - Ultra-fast JavaScript bundler and dev server
- **React** - UI framework for the chatbox components
- **TypeScript** - Type-safe development
- **TailwindCSS** - Utility-first CSS framework
- **Web Components** - Custom HTML elements for embedding

#### Key Packages
- `@chaindesk/embeds` - Main package containing the widget code
- `@chaindesk/ui` - Shared UI components and chatbox logic
- `@chaindesk/lib` - Shared utilities and types

### 3. How the Build System Works

The build process is handled by ESBuild configuration in `packages/embeds/esbuild.config.mjs`:

```javascript
const isProd = process.env.NODE_ENV === 'production';
const outDir = isProd ? './dist' : './tests/dist';

let ctx = await esbuild.context({
  entryPoints: [
    'js/chatbox/index.ts',
    'js/chatbox/legacy.js', 
    'js/form/index.ts',
  ],
  bundle: true,
  outdir: outDir,
  format: 'esm',
  // ... other configuration
});
```

#### Development vs Production Configuration

**Development Mode:**
- Output: `./tests/dist/`
- Serves from: `http://localhost:8000`
- Source maps: Enabled
- Minification: Disabled

**Production Mode:**
- Output: `./dist/`
- Serves from: `https://cdn.jsdelivr.net/npm/@chaindesk/embeds@latest`
- Source maps: Disabled
- Minification: Enabled

## How the Widget System Works

### Bubble Widget Architecture

The bubble widget consists of several layers:

1. **Entry Point** (`js/chatbox/index.ts`)
   - Exports `initBubble` and `initStandard` functions
   - Handles module loading and initialization

2. **Bubble Component** (`js/chatbox/bubble/bubble.tsx`)
   - Creates custom web component `chaindesk-chatbox-bubble`
   - Wraps React components in Web Components API

3. **Initialization Logic** (`js/chatbox/bubble/init.ts`)
   - Handles widget setup and configuration
   - Manages DOM insertion and styling
   - Provides widget control methods (open, close, toggle)

4. **UI Components** (`packages/ui/`)
   - `ChatBoxLoader` - Main chatbox logic and API integration
   - `ChatBubble` - Bubble UI component
   - `ChatboxNavBarLayout` - Standard layout component

### Widget Control Methods

The widget exposes several methods for programmatic control:

```javascript
const widget = await Chatbox.initBubble({
  agentId: 'your-agent-id'
});

// Control methods
widget.open();              // Show the chatbox
widget.close();             // Hide the chatbox  
widget.toggle();            // Toggle visibility
widget.createNewConversation(); // Start new conversation
```

## CDN Deployment Process

### Understanding the Production Pipeline

The production version follows this flow:

1. **Build Process**
   ```bash
   cd packages/embeds
   NODE_ENV=production pnpm build
   ```

2. **Package Publishing**
   ```bash
   pnpm embeds:publish
   ```
   This command:
   - Builds production bundles
   - Increments package version
   - Publishes to npm registry

3. **CDN Distribution**
   - npm package is automatically available on jsdelivr CDN
   - URL: `https://cdn.jsdelivr.net/npm/@chaindesk/embeds@latest/dist/chatbox/index.js`

### Production Usage

Once published, users can embed the widget like this:

```html
<script type="module">
  import Chatbox from 'https://cdn.jsdelivr.net/npm/@chaindesk/embeds@latest/dist/chatbox/index.js';

  const widget = await Chatbox.initBubble({
    agentId: 'cmchosgmh0004mzeuk6xh8far',
  });

  widget.open();
</script>
```

## VPS Deployment Options

When deploying to a VPS, you have several better alternatives than pointing your CDN directly to localhost:8000:

### Option 1: Production Build + Nginx (Recommended)

This is the most robust approach for production:

1. **Build Production Assets**
   ```bash
   cd /path/to/databerry/packages/embeds
   NODE_ENV=production pnpm build
   ```
   This creates optimized, minified files in the `dist/` directory.

2. **Set up Nginx to Serve Static Files**
   ```nginx
   # /etc/nginx/sites-available/cdn.exampledomain.com
   server {
       listen 80;
       server_name cdn.exampledomain.com;
       
       # Serve the embeds files
       location /embeds/ {
           alias /path/to/databerry/packages/embeds/dist/;
           
           # CORS headers for cross-origin requests
           add_header Access-Control-Allow-Origin *;
           add_header Access-Control-Allow-Methods 'GET, OPTIONS';
           add_header Access-Control-Allow-Headers 'DNT,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type,Range';
           
           # Cache static assets
           expires 1y;
           add_header Cache-Control "public, immutable";
           
           # Handle OPTIONS requests for CORS
           if ($request_method = 'OPTIONS') {
               return 204;
           }
       }
       
       # Optional: redirect root to main site
       location / {
           return 301 https://yourmainsite.com$request_uri;
       }
   }
   ```

3. **Enable and Restart Nginx**
   ```bash
   sudo ln -s /etc/nginx/sites-available/cdn.exampledomain.com /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl restart nginx
   ```

4. **Update Your HTML to Use the CDN**
   ```html
   <script type="module">
     import Chatbox from 'https://cdn.exampledomain.com/embeds/chatbox/index.js';
     
     const widget = await Chatbox.initBubble({
       agentId: 'cmchosgmh0004mzeuk6xh8far',
     });
   </script>
   ```

### Option 2: Nginx Proxy to Development Server

If you want to keep using the development server (not recommended for production):

```nginx
# /etc/nginx/sites-available/cdn.exampledomain.com
server {
    listen 80;
    server_name cdn.exampledomain.com;
    
    location / {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # CORS headers
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods 'GET, OPTIONS';
        add_header Access-Control-Allow-Headers 'DNT,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type,Range';
        
        # Handle OPTIONS requests
        if ($request_method = 'OPTIONS') {
            return 204;
        }
    }
}
```

### Option 3: Docker + Nginx

For a more containerized approach:

1. **Create a Dockerfile for the embeds service**
   ```dockerfile
   # packages/embeds/Dockerfile
   FROM node:18-alpine AS builder
   
   WORKDIR /app
   COPY package.json pnpm-lock.yaml ./
   RUN npm install -g pnpm && pnpm install
   
   COPY . .
   RUN NODE_ENV=production pnpm build
   
   FROM nginx:alpine
   COPY --from=builder /app/dist /usr/share/nginx/html
   
   # Custom nginx config
   COPY nginx.conf /etc/nginx/conf.d/default.conf
   
   EXPOSE 80
   ```

2. **Create nginx.conf for the container**
   ```nginx
   # packages/embeds/nginx.conf
   server {
       listen 80;
       server_name localhost;
       
       location / {
           root /usr/share/nginx/html;
           try_files $uri $uri/ =404;
           
           # CORS headers
           add_header Access-Control-Allow-Origin *;
           add_header Access-Control-Allow-Methods 'GET, OPTIONS';
           add_header Access-Control-Allow-Headers 'DNT,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type,Range';
           
           # Cache headers
           expires 1y;
           add_header Cache-Control "public, immutable";
           
           if ($request_method = 'OPTIONS') {
               return 204;
           }
       }
   }
   ```

3. **Build and run the container**
   ```bash
   cd packages/embeds
   docker build -t chaindesk-embeds .
   docker run -d -p 8080:80 --name embeds-cdn chaindesk-embeds
   ```

4. **Proxy through main Nginx**
   ```nginx
   server {
       listen 80;
       server_name cdn.exampledomain.com;
       
       location / {
           proxy_pass http://localhost:8080;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
       }
   }
   ```

## SSL/HTTPS Setup

For production, you'll want HTTPS:

### Using Certbot (Let's Encrypt)

```bash
# Install certbot
sudo apt update
sudo apt install certbot python3-certbot-nginx

# Get SSL certificate
sudo certbot --nginx -d cdn.exampledomain.com

# Auto-renewal (optional)
sudo crontab -e
# Add: 0 12 * * * /usr/bin/certbot renew --quiet
```

Your nginx config will be automatically updated to include SSL.

## Why Not Point CDN to localhost:8000?

**Problems with pointing CDN directly to localhost:8000:**

1. **Development Server**: ESBuild's dev server is meant for development, not production
2. **Performance**: No optimization, minification, or caching
3. **Reliability**: Dev server can crash or restart
4. **Security**: Development mode may expose debug information
5. **CORS Issues**: Dev server may not handle CORS properly
6. **Resource Usage**: Keeps build process running unnecessarily

**Better Approach:**
- Build static production assets
- Serve them with a proper web server (Nginx)
- Use caching and compression
- Implement proper CORS headers
- Set up SSL/HTTPS

This gives you better performance, reliability, and security for your CDN.
